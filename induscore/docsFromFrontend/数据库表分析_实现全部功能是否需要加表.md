# 实现全部功能 — 数据库表分析

结论：**要实现《TODO_待做功能清单》中的全部功能，需要新增若干张表**；现有表可覆盖认证、检测、大屏、历史查询、缺陷详情、生产线列表及控制/编辑/摄像头配置，无需为这些功能加表。

---

## 一、当前已有表（V1 + V2）

| 迁移 | 表名 | 用途 |
|------|------|------|
| V1 | `users` | 用户（无 department_id、phone） |
| V1 | `roles` | 角色 |
| V1 | `permissions` | 权限 |
| V1 | `user_roles` | 用户-角色 |
| V1 | `role_permissions` | 角色-权限 |
| V2 | `detection_records` | 检测记录 |
| V2 | `process_records` | 缺陷处理记录 |
| V2 | `production_lines` | 生产线 |
| V2 | `cameras` | 摄像头 |
| V2 | `stations` | 工位 |

**结论**：  
- **生产线**：启停、编辑、摄像头配置 只需在现有 `production_lines`、`cameras` 上做 UPDATE/状态字段，**不需要新表**。  
- **用户/角色**：增删改用户、编辑角色、重置密码、切换状态 都用现有 `users`/`roles`/`user_roles`/`role_permissions`，**不需要新表**（若要做“按部门筛选”，见下文部门表）。

---

## 二、按功能看是否需要加表

| 待做功能 | 是否需要新表 | 说明 |
|----------|--------------|------|
| 生产线 control / 编辑 / 摄像头配置 | ❌ 不需要 | 用现有 `production_lines`、`cameras` 即可 |
| 用户 CRUD、角色编辑、重置密码、状态切换 | ❌ 不需要 | 用现有 `users`、`roles` 等；若加部门筛选需 `departments` |
| 用户列表按部门筛选、GET /departments | ✅ 需要 | 需 **departments** 表；users 可选加 `department_id` |
| 产品 CRUD（GET/POST/PUT/DELETE /products） | ✅ 需要 | 需 **products** 表；若做“产品-缺陷阈值”可再加 **product_defect_config** |
| 模型上传/部署/下线/对比 | ✅ 需要 | 需 **ai_models** 表；若做多版本可再加 **model_versions** |
| 操作日志 GET /logs/operations | ✅ 需要 | 需 **operation_logs** 表 |
| 通用上传 POST /upload、系统配置 GET /system/config | ❌ 不需要 | 用文件系统 + 配置即可，不必为“上传”单独建表 |

---

## 三、需要新增的表（实现全部功能时）

实现《TODO_待做功能清单》里的**全部**功能时，建议至少新增以下表（并做 Flyway 迁移）。

### 1. departments（部门表）— 对应 GET /departments、用户按部门筛选

- **必须性**：若要做“部门列表”和“用户按部门筛选”，必须加。  
- **可选**：若不做部门，可不加；仅做用户 CRUD 可不加。

```sql
-- 示例结构（可放入 V3 或后续迁移）
CREATE TABLE departments (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(128) NOT NULL,
    code VARCHAR(64) UNIQUE,
    parent_id BIGINT,
    level INT DEFAULT 0,
    sort INT DEFAULT 0,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    CONSTRAINT fk_dep_parent FOREIGN KEY (parent_id) REFERENCES departments(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- 若加部门：可在 `users` 上增加 `department_id`（新迁移里 `ALTER TABLE users ADD COLUMN department_id BIGINT` 等）。

---

### 2. products（产品表）— 对应产品管理全部接口

- **必须性**：产品增删改查、列表都依赖产品表，**必须加**。

```sql
CREATE TABLE products (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(128) NOT NULL,
    model VARCHAR(64) NOT NULL UNIQUE,
    category VARCHAR(32),
    dimensions VARCHAR(128),
    material VARCHAR(64),
    weight DOUBLE,
    surface_treatment VARCHAR(64),
    standard VARCHAR(128),
    threshold DOUBLE,
    target_yield DOUBLE,
    status VARCHAR(16) NOT NULL DEFAULT 'active',
    image_url VARCHAR(255),
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

---

### 3. product_defect_config（产品-缺陷配置表）— 可选

- **必须性**：仅当“按产品配置缺陷类型/阈值”时才需要；若产品表只存基础信息可**先不加**。

---

### 4. ai_models（AI 模型表）— 对应模型上传/部署/下线/对比

- **必须性**：若要做“模型上传、部署、下线、对比”等真实能力，**需要加**；若长期只做 Mock/配置展示可先不加。

```sql
CREATE TABLE ai_models (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(128) NOT NULL,
    version VARCHAR(64) NOT NULL,
    status VARCHAR(32) NOT NULL,
    is_main BOOLEAN DEFAULT FALSE,
    description VARCHAR(512),
    architecture VARCHAR(64),
    accuracy DOUBLE,
    recall DOUBLE,
    f1_score DOUBLE,
    inference_speed DOUBLE,
    size DOUBLE,
    training_data_size INT,
    model_file VARCHAR(255),
    trained_at DATE,
    trainer VARCHAR(64),
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- **model_versions**：仅在做“多版本对比、版本历史”时需要，可后续再加。

---

### 5. operation_logs（操作日志表）— 对应 GET /logs/operations

- **必须性**：若要做“操作日志查询、审计”，**需要加**；若暂不做日志接口可先不加。

```sql
CREATE TABLE operation_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT,
    user_name VARCHAR(64),
    type VARCHAR(32),
    module VARCHAR(64),
    content VARCHAR(512),
    ip VARCHAR(64),
    status VARCHAR(16),
    user_agent VARCHAR(255),
    duration INT,
    created_at DATETIME NOT NULL,
    CONSTRAINT fk_oplog_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 四、汇总结论

| 目标 | 需要新增的表 |
|------|----------------|
| **只做《待做清单》里“不依赖新业务实体”的部分**（生产线控制/编辑/摄像头、用户与角色 CRUD、通用上传、系统配置） | **0 张**，现有表足够 |
| **再加上：部门、产品、操作日志** | **departments**（可选给 users 加 department_id）、**products**、**operation_logs** |
| **再加上：模型管理（上传/部署/下线/对比）** | **ai_models**（及可选 **model_versions**） |
| **再加上：产品-缺陷配置** | **product_defect_config**（可选） |

**直接回答“要实现所有功能是否还需要添加数据库表”：**  
- **是，需要。** 至少需要新增：**products**、**departments**（若做部门与用户按部门筛选）、**operation_logs**（若做操作日志接口）、**ai_models**（若做模型管理真实逻辑）。  
- **不需要新表**即可实现的部分：生产线控制/编辑/摄像头配置、用户与角色增删改与重置密码与状态、通用上传与系统配置（用现有存储与配置即可）。
