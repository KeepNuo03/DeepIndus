# 离线检测「多处缺陷」如何进入「记录管理」—— 从接口到数据库

## 一、结论（先说结论）

**当前实现：一张图无论检出 1 个还是 N 个缺陷，在「记录管理」里都只对应 1 条记录。**

- 接口返回里会把**所有缺陷**都给你（`detections` 数组、`annotated_image` 上也有所有框）。
- 但**落库时只用了「第一个缺陷」**的信息，生成**一条** `detection_records`，所以记录管理里只看到一条；第二、第三个缺陷没有单独写入数据库。

---

## 二、流程梳理（从上传到数据库）

### 1. 离线检测入口

- 请求：`POST /v1/detection/upload`，上传一张图。
- 后端：`DetectionServiceImpl.uploadAndDetect(file, serialNo)`。

### 2. YOLO 返回

- 调用 `yoloService.detectImage(file)`，得到类似：

```json
{
  "code": 200,
  "data": {
    "detections": [
      { "class_id": 5, "class_name": "scratches", "confidence": 0.92, "bbox": { "x1": 10, "y1": 20, "x2": 100, "y2": 200 } },
      { "class_id": 2, "class_name": "patches", "confidence": 0.88, "bbox": { ... } },
      { "class_id": 0, "class_name": "crazing", "confidence": 0.75, "bbox": { ... } }
    ],
    "detection_count": 3,
    "annotated_image": "data:image/jpeg;base64,..."
  }
}
```

- 即：**多个缺陷在 `detections` 数组里**，前端和接口响应里都能看到全部。

### 3. 落库逻辑（关键）

- 接着调用 **`saveDetectionResult(yoloResult, serialNo)`**，内部逻辑是：

```java
List<Map<String, Object>> detections = getList(data, "detections");
boolean hasDefect = detections != null && !detections.isEmpty();

DetectionRecord record = new DetectionRecord();
// ... 设置 detectionNo、serialNo、timestamp、modelName 等 ...

if (hasDefect) {
    Map<String, Object> first = detections.get(0);   // ← 只取第一个
    String defectName = String.valueOf(first.getOrDefault("class_name", "缺陷"));
    String defectType = DefectTypeMapper.normalize(defectName);
    double confidence = toDouble(first.get("confidence"));
    record.setDefect(DefectTypeMapper.displayName(defectType));
    record.setDefectType(defectType);
    record.setSeverity(mapSeverity(confidence));
    record.setConfidence(confidence * 100);
    // position_x/y、area 等当前也未从 first 的 bbox 写入
    record.setStatus("fail");
    // ...
}
recordRepository.save(record);   // 只 save 一条

ProcessRecord processRecord = new ProcessRecord();
processRecord.setDetectionRecord(record);
// ...
processRecordRepository.save(processRecord);   // 只一条处理记录
```

- 也就是说：**只根据 `detections.get(0)` 填一条 `DetectionRecord`，然后 `save` 一次**；第二、第三个缺陷既不生成新记录，也不写入任何表。

### 4. 数据库里实际长什么样

- 表：**`detection_records`**（一条记录 = 一次检测事件，当前设计 = 一张图一次上传）
  - 每条记录只有**一个** `defect` / `defect_type` / `confidence` / `severity`，以及可选的 `position_x`、`position_y`（当前代码里这两处也未从 bbox 写入）。
- 表：**`process_records`**
  - 通过 `detection_id` 关联某一条 `detection_records`，记录「谁在什么时候对该次检测做了什么」（如 AI 创建、人工复核）。  
- 因此：**一次上传 = 1 行 detection_records + 1 行 process_records**；多出来的缺陷只在接口的 `detections` 和标注图里，**没有单独进库**。

---

## 三、和「记录管理」的关系

- 「记录管理」列表来自：**`GET /v1/records/query`**，查的就是 **`detection_records`** 表（分页、筛选、搜索）。
- 因为每次上传只插入 **1 条** `detection_records`，所以：
  - **一张图 1 个缺陷** → 记录管理里 1 条；
  - **一张图 N 个缺陷** → 记录管理里还是 **1 条**，且这条里的缺陷类型/置信度等**只对应第一个缺陷**。

---

## 四、总结表

| 层级 | 行为 |
|------|------|
| **YOLO / 接口返回** | 返回所有缺陷：`detections[]`、`annotated_image` 上所有框。 |
| **saveDetectionResult** | 只取 `detections.get(0)`，生成 1 条 `DetectionRecord` 并写入 DB。 |
| **detection_records 表** | 一次上传只插入 1 行；多缺陷时只保存「第一个」的信息。 |
| **process_records 表** | 每条对应上述那 1 条 detection_record，记录创建/复核等。 |
| **记录管理** | 列表 = detection_records，所以多缺陷图在列表里仍只显示 1 条。 |

---

## 五、若希望「多处缺陷 → 多条记录」

若业务上需要：**每个缺陷在记录管理里单独一行**（便于按缺陷类型统计、按单缺陷复核等），需要调整设计和实现，例如：

1. **方案 A：一张图对应多条 detection_records**  
   - 在 `saveDetectionResult` 里对 `detections` **循环**，每个 detection 生成一条 `DetectionRecord`。  
   - 需要解决：同一张图的多条记录如何关联（例如共用一个 `batch_id` 或 `detection_no` 前缀 + 序号），以及 `detection_no` 当前是唯一键，需要改为「一次上传一个 batch，多条记录用 batch + 序号」等。
2. **方案 B：主从表**  
   - 保留「一次上传一条主记录」（如 `detection_records` 只存图片/时间/序列号等），另增从表（如 `detection_defects`）存每个缺陷的类型、置信度、bbox 等，记录管理列表可以继续查主表，详情页再查从表展示多缺陷。  

当前代码和数据库都**没有**「一缺陷一行」的设计；若要，需要按上面之一做表结构/唯一键/保存逻辑的改造。  
本文档仅说明**当前**「离线检测多缺陷如何进入记录管理」的实际情况与数据库表现。
