# 离线上传与重试机制

## 目标
在弱网/断网环境下保证抽检图片最终可达、结果可追踪、避免重复入库。

## 机制总览
1. 上传任务先写本地 `upload_queue`（status=pending）。
2. 网络可用时执行上传。
3. 请求必须带 `Idempotency-Key`。
4. 成功后标记 `completed`，记录 `serverRecordId`。
5. 失败后标记 `failed`，记录 `lastError` 并递增 `retryCount`。
6. 自动重试达到上限后标记 `dead`（需人工处理）。
7. `WorkManager` 周期性扫描可重试任务；支持“立即同步”和“手动重试”。

## 幂等策略
- 一个业务动作绑定一个 `idempotencyKey`。
- 重试必须复用同 key。
- 服务端若已处理，客户端应读状态接口而非重复创建数据。

## 代码位置
- 队列表：`UploadQueueEntity.kt`
- 队列 DAO：`UploadQueueDao.kt`
- 重试 Worker：`android-app/app/src/main/java/com/induscore/mobile/worker/UploadQueueWorker.kt`
- 后端上传接口：`POST /v1/mobile/uploads/sampling`
- 后端状态接口：`GET /v1/mobile/uploads/{idempotencyKey}`

## 推荐重试参数
- 最大自动重试次数：5（已实现）
- 退避策略：指数退避（10s, 30s, 60s, 120s, 300s）
- 网络约束：仅 `CONNECTED`

## 已落地恢复闭环（当前版本）
- 上传状态页支持：
  - 立即同步队列
  - 重试全部失败任务
  - 仅重试超重试任务（`dead`）专项入口
  - 单条失败任务手动重试
  - 清理历史完成记录
  - 清理终态记录（`dead + completed`）
  - 终态治理统计面板（pending/uploading/failed/dead/completed）
- 状态语义：
  - `pending` 待上传
  - `uploading` 上传中
  - `failed` 自动重试中
  - `dead` 超出自动重试上限，等待人工处理
  - `completed` 完成
- 审计日志：
  - 本地新增 `upload_operation_log`，记录人工重试/同步/清理操作结果
  - 上传状态页展示“最近操作记录”（成功/失败、作用域、影响条数、提示信息）
- 网络类型差异化策略：
  - 队列任务支持 `networkState` 策略：`wifi_only`（默认）与 `any`
  - 自动与普通“立即同步”遵循策略：`wifi_only` 任务仅在 Wi-Fi 上传
  - 上传状态页提供“立即同步（允许蜂窝）”人工兜底入口，可临时突破策略
  - 新增蜂窝阈值守卫（双阈值）：
    - 任务数阈值：`CELLULAR_SYNC_TASK_THRESHOLD=3`
    - 总流量阈值：`CELLULAR_SYNC_TOTAL_BYTES_THRESHOLD=20MB`
  - 超阈值时先弹出风险确认；若未确认，任务保持 `pending`，并记录提示原因
  - Worker 侧同样有阈值兜底，避免其他入口绕过前端确认
  - 抽检上传页不再让用户手输网络策略，统一默认策略为 `wifi_only`（用户中心设计）

## 风险
- 本地文件被用户删除时会导致无法重试，需在 UI 显示可恢复提示。
- 服务端上传状态当前内存态，生产建议改为持久化。
