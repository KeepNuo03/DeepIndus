# 真实产线试点压测方案（弱网 + 蜂窝切换）

## 目标
- 在真实试点线体验证移动端上传闭环在复杂网络条件下的稳定性。
- 验证以下指标是否达标：
  - 上传闭环率（目标 >= 95%）
  - 失败恢复成功率（目标 >= 99%）
  - 上传状态查询接口 P95（目标 <= 500ms）

## 压测范围
- 页面链路：
  - `抽检上传`（入队）
  - `上传状态`（同步、重试、清理、日志）
- 功能链路：
  - 自动重试 + `dead` 人工重试
  - Wi-Fi 优先策略（`wifi_only`）
  - 允许蜂窝同步（含阈值告警与人工确认）

## 前置条件
- 后端服务：`/v1/mobile/uploads/sampling`、`/v1/mobile/uploads/{idempotencyKey}` 可用。
- 安卓构建版本：包含“蜂窝阈值策略与确认弹窗”的版本。
- 测试账号：至少一个管理员账号。
- 测试设备：至少 1 台真实安卓手机（建议再配 1 台备用机做交叉验证）。
- 网络准备：
  - 现场 Wi-Fi（可稳定连接）
  - 运营商蜂窝网络（4G/5G）
  - 弱网模拟工具（路由限速/丢包，或测试手机系统网络限制）

## 数据准备
- 抽检图片集建议 30~60 张，覆盖：
  - 小图（< 1MB）
  - 中图（1~5MB）
  - 大图（> 8MB）
- 每轮压测至少触发 20 条上传任务，保证统计有效。

## 场景设计

### 场景 A：稳定 Wi-Fi 基线
1. 在稳定 Wi-Fi 下连续入队 20 条任务。
2. 点击“立即同步队列”。
3. 记录上传完成数、失败数、恢复数与耗时。

验收：
- `completed / total >= 95%`
- `dead` 任务应接近 0（异常时需记录原因）

### 场景 B：弱网抖动（Wi-Fi）
1. Wi-Fi 限速 + 丢包（建议 10%~20% 丢包，时延 200~500ms）。
2. 连续入队 20 条任务并触发同步。
3. 观察 `failed -> retry -> completed/dead` 转换与操作日志。

验收：
- 自动重试后恢复成功率 >= 99%
- `dead` 任务可通过“仅重试超重试任务（dead）”恢复或明确终态

### 场景 C：Wi-Fi 断开 -> 蜂窝切换
1. 先在 Wi-Fi 入队 10 条任务，不立即同步。
2. 断开 Wi-Fi，保持蜂窝网络。
3. 在“上传状态”点击“立即同步（允许蜂窝）”。
4. 若超过阈值，确认弹窗出现后分别验证“取消”和“仍然继续”。

验收：
- 超阈值时必须出现风险提示
- 取消后任务保持 `pending`
- 确认后开始上传并产生日志记录

### 场景 D：蜂窝阈值边界
1. 任务数阈值边界：3 条与 4 条分别测试。
2. 流量阈值边界：总大小 20MB 左右分别测试（19MB / 21MB）。

验收：
- 不超阈值：允许直接触发蜂窝同步
- 超阈值：必须先确认，再同步

## 指标口径
- 上传闭环率 = (`completed` + 可人工处理恢复完成) / 总入队数
- 失败恢复成功率 = 恢复成功数 / (`failed` + `dead`) 总数
- 上传状态查询 P95：
  - 对同一批任务重复查询状态接口，记录响应耗时
  - 统计 95 分位耗时

## 现场执行建议
- 每个场景至少执行 2 轮，取均值。
- 每轮执行后导出：
  - 队列快照（pending/uploading/failed/dead/completed）
  - 最近操作日志截图
  - 关键异常截图与时间点

## 失败处理策略
- 若闭环率或恢复率不达标：
  - 先定位是否集中在大图、弱网峰值或蜂窝切换瞬间
  - 检查 `lastError` 高频类型
  - 回放操作日志并提炼前三大失败原因
- 若 P95 超标：
  - 区分客户端问题（UI 阻塞/频繁刷新）与服务端问题（接口时延）

## 输出物
- 使用 `15_真实产线试点压测记录模板.md` 回填每轮结果。
- 最终形成“是否达标”的结论与整改清单（按 P0/P1 优先级排序）。
